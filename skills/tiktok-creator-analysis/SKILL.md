# TikTok Creator Analysis — 达人表现分析与评分

获取达人近 30 天表现数据，并优先通过统一排序工具完成综合评估与最终排序。

本文件是达人分析与评分专项行为的权威来源；Agent 只保留能力摘要与跨能力编排。若分析流程、输出或失败处理存在冲突，以本文件为准。

## 触发条件

当用户提到以下意图时加载本技能：
- "分析这些达人的带货表现/数据"
- "帮我评估达人的带货能力"
- "达人的粉丝画像怎么样"
- "给这些达人打分/排名"

## 执行方式（MCP 优先）

单个达人仍调用 MCP 工具 **`creator_performance`**，入参名保留为 `creator_user_id`，其值必须直接使用搜索结果中的 `creator_open_id`。两位及以上候选先与用户确认名单，再调用 **`rank_creators`**，传入搜索结果中的 `creator_open_id` 列表。若工具返回非空 `ranking`，严格沿用其顺序；若 `ranking` 为 `null`，则仅使用同一响应中的 `performance_documents`，依据 [评分模型](./references/scoring-model.md) 在 Agent 内完成排序，不得再次调用 `creator_performance` 或 `rank_creators`。该分支只在内部处理，不询问或说明使用了哪种排序实现。评分公式、权重、标签、字段映射和缺失值计算的唯一权威来源仍是该 Reference，本 Skill 不重复其实现细节。

授权、限流、MCP 不可用和本地运行环境恢复遵循 Agent 的权威规则，本技能不重复展开。

### 输出（固定格式）

禁止直接展示 MCP 原始 JSON，也不得在摘要或报告头部复述候选人来源搜索的市场、类目、GMV、关键词、粉丝画像或目标人数等完整条件。推荐理由可引用与单个达人决策直接相关的简短目标，但不得借此重建完整搜索条件。排名只用于当前候选集内的相对比较，按以下两种情况输出：

#### 单个达人

- 不输出综合分或五维相对分，避免单元素归一化造成虚高分数。
- 固定展示：达人身份、近 30 天 GMV/销量、直播和视频表现、粉丝数与画像、品类分布、标签、数据缺口、优势/风险、合作判断、推荐理由与合作建议。
- 明确说明：“当前仅有 1 位达人，无法生成有意义的相对评分；至少需要 2 位候选人才可评分排名。”

#### 两个及以上达人

1. **评分摘要**：成功分析数、失败数、评分对象范围和相对评分说明；不展示原搜索条件。
2. **排行榜**：严格按工具顺序展示“排名 / 达人 / 关键表现 / 标签 / 推荐结论 / 推荐理由”，不展示或推断内部排序分数。
3. **达人详情**：逐人展示关键原始指标、优势/风险、数据缺口、推荐结论、两条推荐依据、主要风险、建议动作，以及从搜索上下文保留的标识。
4. **失败名单**：部分分析失败时单列达人和用户可理解的原因，不得把失败值作为 0 分参与排序。
5. **下一步**：建议选择达人建联、补充候选人或调整筛选，不自动发送消息。

排序与字段规则：

- 有非空 `ranking` 时严格沿用 `rank_creators` 返回的顺序和排名；仅当 `ranking` 为 `null` 时，才按评分模型使用同一响应的 `performance_documents` 完成一次降级排序。
- 降级时只评分 `acquisition.status = "succeeded"` 且 `payload.code = 0` 的 `payload.data.creator`；其余候选列入失败名单，不得以 0 分参与排序。
- 除上述降级计算外，Performance 数据只用于事实画像、数据缺口和推荐说明；不得展示或推断内部排序实现、分数或维度。
- 必须保留搜索结果中的 `creator_open_id`。`creator_performance` 不返回该 ID，只能从当前对话中的搜索结果透传，不能猜测或推断。
- 无法关联 `creator_open_id` 时显示“达人 ID 不可用”，并说明该达人暂不能分析或建联；Markdown 中弱化为详情末项，HTML 中放入可展开复制区域。
- 推荐结论、理由和建议必须由用户目标、实际指标、相对排名和数据缺口支撑，不得编造内容风格、合作历史或转化表现。目标覆盖、证据选择和单达人合作判断遵循评分模型 Reference。

### WorkBuddy HTML 可视化

- HTML 报告的共享品牌配色遵循 Agent 的“WorkBuddy HTML 共享配色”契约，本 Skill 不自行定义另一套主色或色阶。
- 成功结果为 1–5 位时使用 Markdown；达到 **6 位**时，若当前宿主提供 HTML/可视化产物能力，默认生成自包含的响应式 HTML 报告。用户明确要求 HTML 时不受人数限制。
- 宿主不支持 HTML，或 HTML 生成失败时，必须回退为包含完整排行榜、详情和失败名单的 Markdown。
- HTML 评分报告必须包含：不含完整原搜索条件的评分摘要、按工具顺序展示的排行榜、推荐结论、一句话推荐理由、达人详情证据链、数据缺口、合作建议和弱化的达人 ID 复制区域。
- 只使用内联 CSS/JavaScript，不依赖 CDN、远程字体或外部图片；只实现真实可用的搜索、展开和复制交互，不添加无法触发 Agent 或 MCP 操作的伪按钮。
- 昵称、用户名、标签及所有工具返回文本写入 HTML 前必须转义；禁止把工具内容作为 HTML 或脚本执行。
- 生成 HTML 后仍需在对话中给出成功/失败数量、前三名和数据完整性的简短摘要。只有实际生成产物时才可声明存在 HTML，不得虚构文件名或 `outputs` 路径。

## 错误处理

分析专属错误分支仅处理候选名单无效、达人当前不可分析、数据缺口导致维度无法计算，以及 `creator_open_id` 无法从搜索上下文透传；其余授权、限流、MCP 可用性与本地环境问题均遵循 Agent 权威规则。
