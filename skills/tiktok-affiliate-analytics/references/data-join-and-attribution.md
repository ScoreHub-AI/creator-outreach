# 数据关联与归因 Reference

本文件是订单筛选、去重、归因和 TOPN 排序解释的 owner。计算由后端完成，Skill 不执行 SQL，也不重算或改排后端榜单。

## 日期轴

- 店铺/商品日报使用各自 `metric_date`；
- 联盟订单使用 `xmj_affiliate_order_line.biz_date`，表示联盟订单创建业务日；
- 订单详情使用其自身订单事实日期，仅用于订单事实关联和金额重建，不能替代联盟订单的 `biz_date`；
- 退款/取消使用各自事实表 `biz_date`；
- 不同事实必须保留各自日期轴，不用一个笼统统计日期替代。

## 核心关联

- 店铺隔离必须使用 `shop_id`；订单关联使用 `(shop_id, order_id)`；
- 商品和 SKU 识别必须以目标商品关联规则为准；一个目标商品存在多个联盟 SKU 时，先确认订单详情中的 SKU 与商品 ID 映射，再按订单级目标商品折叠；
- 联盟订单的达人标识优先使用非空、规范化的 `creator_username`；`target_collaboration_id` 只作为可选定向合作链路标签，不能据此推断达人身份。官方画像调用前才解析 `creator_open_id`；
- 订单详情金额先按 `(shop_id, order_id)` 聚合，再按目标商品订单行取 `sale_price`；不使用重复保存的订单级小计或运费字段直接求和；订单详情的支付时间或状态不参与有效联盟订单筛选。订单详情中的 `payment_sub_total`、`payment_shipping_fee` 属于可能在同一订单多行重复保存的订单级字段，禁止直接按订单行求和。

## 有效联盟订单

仅当 `xmj_affiliate_order_line.biz_date` 在分析范围内，且 `target_collaboration_id` 或 `creator_username` 至少一个有效非空值时，订单才进入有效联盟订单集合；`NULL`、空字符串和仅含空格的值均视为空值。订单数按 `DISTINCT order_id` 统计。`order_status` 为空或不可用时不得以其单独判定有效性。

不自动排除取消或退款订单；取消和退货作为独立结果指标。联盟订单行数不得替代订单数；多商品订单在店铺或商品粒度按各自统计对象计数，多达人订单可分别计入达人归因结果，但不得将达人结果之和解释为店铺订单总数。

## Tiky GMV

对目标商品先形成订单级金额：

1. 按 `(shop_id, order_id)` 聚合订单详情；
2. 只汇总目标商品订单行 `sale_price`；
3. 排除运费；
4. 目标商品多个联盟 SKU 先折叠，避免同一商品金额重复累加；
5. 多达人订单允许按各达人归因明细分别计入，跨达人汇总可能重复；
6. 目标商品售价缺失时金额未知，但订单数和销量可保留。

金额覆盖不足时不得将缺失金额填 0 后参与金额排名；应披露金额覆盖率和未重建金额数量。商品日报联盟 GMV 不得替代达人明细金额。

## 履约与官方画像

履约达人数、履约后出单达人数和履约内容只沿用“定向合作 + 免费样品申请 + 履约链路”的驾驶舱口径；公开合作不纳入履约覆盖。履约链路出单达人数与全联盟订单关联达人数量是不同指标，不得合并。`creator_username` 无法可靠映射到 `creator_open_id` 时，不猜测 ID，保留未映射记录并降低官方画像覆盖率。

## 覆盖率与降级

- 任一跨表关联失败时，保留可取得的订单数、销量或汇总事实，并记录未关联数量；
- 订单详情金额关联不足时，金额指标标记 `partial` 或未知；
- 达人身份映射不足时，本店历史结果仍可输出，官方画像标记 `partial`；
- 多 SKU 折叠规则未通过真实数据核验前，不把联盟明细行数直接当作目标商品销量或金额；
- 所有金额、销量和达人排名结果必须标明来源口径，禁止跨事实表反推。

派生指标统一遵循：商品有效联盟订单数在有效集合上增加目标 `product_id` 后按订单去重；达人有效联盟订单数在有效集合上增加规范化非空 `creator_username` 后按订单去重；商品订单关联达人数量在商品有效联盟订单集合中对规范化 `creator_username` 去重；商品订单趋势按 `biz_date` 聚合。

TOPN 正常排序为 Tiky GMV 降序、有效联盟销量降序、有效联盟订单数降序、creator_username 升序。金额缺失时，TOPN 不以 0 填充金额；保留缺失标识，并按可用销量、有效联盟订单数进行降级排序，同时说明金额覆盖范围和未重建金额数量。后续专题在实现前仍需单独确认：内容订单关联日期轴、`content_id + product_id + 归一化 content_type` 的完整关联与覆盖率、取消/退货同一订单行多条记录的最终去重键、达人/内容售后归因规则、履约弱点的相对比较基准，以及样品申请—履约—出单转化漏斗是否可计算。
