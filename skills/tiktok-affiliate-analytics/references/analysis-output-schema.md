# 分析输出结构与规则 Reference

## 输出顺序

默认按以下顺序输出：

1. 核心结论摘要；
2. 关键数据事实；
3. 趋势或同口径周期比较（如有）；
4. 风险点与机会点（如有）；
5. 数据限制与覆盖率；
6. 人工决策建议（如有）。

首次店铺整体分析覆盖店铺经营总览与趋势诊断、联盟经营贡献与渠道结构、商品整体经营表现与风险；用户明确指定商品或达人时，只展示指定对象相关信息；订单或内容仅在一期已有可靠关联事实时展示，不能暗示独立订单/内容专题已实现。执行过的关联分析不必全部展示，只有具备业务价值且证据充分时才展开。

默认用户可见内容至少包括：分析对象、实际分析时间范围、关键指标来源与口径、会影响结论的数据状态，以及必要的金额/关联覆盖率和数据限制。内部保留的技术字段不必默认展开，但不能因此省略影响结论的上下文。

## 摘要规则

- 通常选择 1–3 条最重要结论；
- 每条结论标明对象和结论类型，并给出关键数值；
- 区分事实、观察性判断、风险/机会和人工建议；
- 不在摘要倾倒完整指标字典或未经证据支持的行动结论。

摘要至少覆盖店铺、商品、达人、订单、内容五类核心业务对象的适用边界：有对象结果时围绕该对象摘要；没有该对象可靠结果时不强行补充。

趋势或环比在具备可比周期时，原则上同时给出当前周期值、对比周期值、绝对变化值和变化率；缺少可比周期、分母为 0 或口径不一致时，按 `not_comparable` 说明原因。

## 必须保留的上下文

内部结果至少保留店铺、市场、请求与实际日期范围、样本量、事实日期轴、指标来源、去重键、数据状态、金额/关联覆盖率、未映射和不可分析数量。用户追问计算方式或完整性时再展开技术细节。每条趋势、风险或机会还应保留支撑事实、比较周期、样本量和覆盖率，确保结论可追溯。

## 状态与建议

状态解释、结论强度和范围外回复遵循 [业务规则](./business-rules.md)。后端未提供的覆盖率和技术上下文标记未知，不凭空补齐。多个店铺各自展示，保留实际币种。

生成 WorkBuddy HTML 报告时，共享品牌配色遵循 Agent；外部名称、文本和链接必须转义，只展示本次真实结果，并提供实际生成文件的可用链接。
