# 随手查：编号、真实关系与读取缺口

一期整理稿 · 保留样品、回复/聊天、任务追溯、邮件/成员定位所需标识及CRM关联限制；出现CRM对象用于说明不可混用，不表示已接入CRM工具。[公共契约](./common-contract.md)约束类型与可信绑定，范围见03（开发对照，不随包发布），调用见[Agent](../../tiktok-creator-outreach.lookup-additions.md)。

## 1. 不可互换的标识

| 对象 | 区分与使用 |
| --- | --- |
| 登录成员/商户 | 当前操作身份由可信端提供；被查成员UUID只是业务对象。T39成员ID不当authUserId，更不能借ID替换调用者 |
| 平台/云端/CRM店铺 | 各源shopId、CRM内部shopId、datahouse店铺代码/编号须可靠映射；同字段名或店名不证明相同。当前选店不是模型自由参数 |
| 品牌 | CRM品牌UUID不同于店铺ID。合作属于一个品牌，店铺绑定一个品牌，但同品牌可有多店；品牌范围不自动等于本店范围 |
| 达人账号 | 准确tk_id/账号不同于昵称、URL；模糊关键词不证明唯一身份。不要擅改字符或把带@文本未经核对当准账号 |
| 达人内部/平台编号 | 平台达人UID、CRM merchant_creator_id/内部达人UUID、云端creatorId/任务达人行ID属于不同标识；须依源字段及可读映射使用，不因值看似相同互换 |
| 样品申请 | 平台applicationId不同于云端本地id、平台订单号、运单号；T02只收平台申请编号。一次达人可有多条申请，达人组数≠申请条数 |
| CRM品牌资源/合作 | opportunity_id、cooperation_id与人类可见合作编码区分。归属记录/建联凭证属于资源历史，不自动是某次合作历史 |
| CRM寄样 | sample_id/寄样编码不同于平台申请编号。SAMPLE_LIST导出为CRM寄样，不是官方样品申请导出 |
| 商品 | CRM商品UUID不同于平台PID/product_id；同名不证明同商品。商品店铺关系须从可靠字段读取，不凭品牌或标题推断 |
| 规格 | 平台SKU ID、seller_sku、CRM规格标识按源区分。商品级内容不证明每个SKU均已完成内容履约，价格“分”字段无币种不猜CNY |

所有业务ID在模型边界用string；平台长编号不丢精度。不能用数组位置、同名、文本相似、同达人/商品或时间接近构造关系。


## 3. 申请到CRM的现状、目标与真实关系（U27）

原包记载：写入流程有匹配/创建或复用合作及寄样逻辑，缺审核人且有活跃合作可复用负责人；samples.application_id有存储线索，但原已核只读入口未暴露可靠映射，写sync能返回建单结果不能用于只读代查。

本轮确认新增CRM专门只读关联入口，T02先云端详情校验、再CRM查真实关联合并。不可用订单、同达人/商品/品牌猜连，CRM须独立校验商户/当前店铺及嵌套关系。

返回当前真实关联合作/寄样、合作摘要、寄样摘要及已有可靠集成状态/原因，缺原因未知，不要求完整失败追踪。多申请可复用同合作，合作内容不能逐申请/SKU重复认领。成功未匹配、原因无记录和读取失败分开；当前未发现关系不证明从未建单。接口未具备时正确受限不等于一期目标完成。

新CRM入口在一次响应内返回上述事实，T02不再查寄样列表；只纳入当前申请真实关联寄样，不由共同合作/PID推出申请关系。当前有权且真实关联的已结束合作保留；关联、合作摘要、寄样摘要分层说明可用性，摘要失败不能抹去可靠关联。平台与CRM商品、运单、状态分别保留来源，CRM商品SKU名称不冒充平台SKU ID。S37后续复用仍适用事实，业务流程不变，不自动纳入全套领域工具。

正式只读契约及证据见07（开发对照，不随包发布），不调用写sync补查询。

## 4. 时间与证据

createdAtOfficial与appliedAtOfficial保留原义，T01实际筛前者；读取时刻、单条lastSyncAt与共享刷新finishedAt各不同，不能互代或证明全店全历史完整。多申请可能复用一张合作，合作内容不逐条归给每个申请或SKU。接口关联未知时停止，不补写或猜测。

## 5. 回复、私信任务与邮箱标识

| 标识 | 真实用途与不可互换项 |
| --- | --- |
| notification_id | 当前成员当前店铺的通知主键，不是messageId、达人号、taskId或任务达人行；先核对象才返回/标读 |
| creatorImId / IM tkUid | T07已有聊天的两种可靠定位入口；仅tkUid先conversation定位creatorImId。账号/昵称/openId/任意conversationId不能替代；IM tkUid与任务侧UID按来源核关系，不因名称相近互换 |
| 通知taskId / versionType | 已存ExtendSendTask私信主任务关系，非官方定向邀约ID；versionType是业务来源，不是另一个主机地址，可空，不由名称猜 |
| task_creator_row_id | 指定主任务下的真实达人行，T14最后messages入口的id；主任务ID、UID或通知ID都不能替代，必须先核父子/达人关系 |
| email_id | 本人配置邮箱的系统邮件记录ID，非主题、messageId、通知编号；T09前核sendType=1及to本人，发件正文走T08 |
| CRM member_id / 云端邮件user/team | CRM成员UUID、云端邮件目标、调用身份与团队编号各不同；T39仅定位业务对象，须可信映射＋授权后T10。authUserId不交模型，不猜同名/邮箱关系，无映射停止 |

S13不为追溯再标通知：真实通知关系→当前任务配置或现存达人发送记录。配置可改、部分消息由当前contents回填，不能当历史原文，不与双向聊天互代。T08/T09邮箱归当前登录成员、非当前店；T10团队统计权限不提供他人正文权。团队名称无可靠定位入口不创造关系，T39不开放本店资格查询。

支撑范围及字段见[支撑工具契约](./reply-support-tool-contracts.md)；通知/聊天、邮件完整字段在各领域参考。
